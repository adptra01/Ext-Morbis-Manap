CRITICAL ISSUES DETAIL
═══════════════════════════════════════════════════════════════════════════════

ISSUE #1: Storage Key Mismatch
  Severity: 🔴 HIGH
  Status: Identified & Documented
  Location: src/features/sidepanel/App.tsx:41-46
  Root Cause: Sidepanel uses direct chrome.storage with 'md-*' prefix keys
              while popup uses background message handler with standard keys
  Impact: Settings toggled in popup won't reflect in sidepanel and vice versa
  Fix Time: 20 minutes
  Solution: Replace direct chrome.storage.sync calls with sendMessage<'GET_ALL'>()
  Difficulty: Easy (straightforward refactor)
  Reference: AUDIT_MIGRATION_VS_DEV.md Section 3 (Storage System)

ISSUE #2: Hardcoded Feature List
  Severity: 🔴 HIGH
  Status: Identified & Documented
  Location: src/features/sidepanel/App.tsx:10-24
  Root Cause: Feature list hardcoded with only 13 features
              Development branch has all 19 features in background config
  Impact: User can't toggle 6 features (batchDelete, resumeTab, etc) from sidepanel
  Fix Time: 30 minutes
  Solution: Fetch feature list from background via sendMessage<'GET_ALL'>()
  Difficulty: Easy (simple data binding change)
  Reference: AUDIT_MIGRATION_VS_DEV.md Section 1 (Feature Parity)

ISSUE #3: Error Handling
  Severity: 🟠 MEDIUM
  Status: Identified & Documented
  Location: All sendMessage() calls in popup and sidepanel
  Root Cause: Missing .catch() handlers and error fallbacks
  Impact: Silent failures possible, difficult debugging
  Fix Time: 10 minutes
  Solution: Add .catch() with fallback to direct storage access
  Difficulty: Easy (add error handlers)
  Reference: AUDIT_MIGRATION_VS_DEV.md Section 4 (Messaging System)
